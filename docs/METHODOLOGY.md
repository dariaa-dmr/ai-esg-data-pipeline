# Methodology

## 1. Scope

The pipeline prepares company-level records for an ESG-oriented map and research dataset. It combines structured company identifiers, public-source information, external enrichment services, geocoding, licensed verification data, rule-based validation, and limited LLM-assisted text editing.

## 2. Initial collection

Company records were assembled into a common CSV schema. The collection stage could include AI-assisted search and drafting, followed by structural and factual checks. The downstream pipeline does not treat generated text as verified evidence by itself; company identifiers and source fields remain necessary for subsequent enrichment and validation.

## 3. CSV versioning and preservation

Working versions were separated from source copies. The operational pipeline used source, backup, archive, and stage-specific directories. These working folders are intentionally excluded from the public repository, while the code that implements the processing logic is retained.

## 4. Parsing and routing

The splitter detects encoding and delimiter, attempts quote-aware parsing, and expects a defined twelve-column source schema. Rows that can be reconstructed safely are written to the clean route. Unresolved rows are preserved in dirty or retry outputs rather than being discarded.

The mature snapshot also records source metadata such as `record_id`, source filename, source row number, physical line, parse status, parse reason, and raw input text.

## 5. Dadata enrichment

Company identifiers, primarily INN, are used to request structured organization data. Enrichment may supply normalized names, addresses, registration status, classification information, and related organization attributes. API credentials are not stored in the public repository.

## 6. Geocoding

Address information is converted into map coordinates through Yandex geocoding. The public snapshot contains the client logic and configuration templates but no credentials or cached service responses.

## 7. Integrity, recovery, and deduplication

The mature pipeline uses stable row identity where possible. Missing immutable source or classification fields can be restored from the clean reference layer. A composite fallback key combines INN, registration region, sector, industry, and subindustry.

This design avoids treating every repeated INN as an accidental duplicate. It also checks that row counts remain stable across restoration stages.

## 8. Legal status and activity

Normalized organization status is used to separate active and inactive records. Records are not silently removed; stage outputs and reports document their route.

## 9. Offline SPARK verification

SPARK is integrated as an offline/manual contour:

1. a request list is prepared;
2. licensed exports are received outside the public repository;
3. structured files are parsed;
4. records are matched by normalized INN;
5. employee, revenue, foundation-year, activity, and evidence fields are attached;
6. records are routed according to the size rules.

Raw licensed exports are excluded from publication.

## 10. Included, excluded, and review routes

The routing layer distinguishes:

- records with sufficient size evidence;
- records with sufficient evidence to demonstrate that they do not satisfy the threshold;
- records with missing, conflicting, or incomplete evidence that require review.

This prevents uncertainty from being converted into automatic exclusion.

## 11. Description construction

Descriptions are generated from structured fields after enrichment and verification. The default fallback is rule-based. When YandexGPT is configured, it is used as a constrained editor rather than as an independent source of facts.

The prompt prohibits internet search, unsupported additions, source-name narration, links, and promotional claims. The fourth sentence containing employee and financial information is generated by rules and must remain unchanged.

Quality checks flag missing descriptions, structural problems, prohibited wording, insufficient factual content, and other review conditions. Full manual review of every description was not performed; manual checks were targeted to flagged, incomplete, and disputed cases.

## 12. Export and quality gate

Included and described records are exported by region, industry, and subindustry. A strict map CSV removes delimiter-breaking characters from public-facing fields and validates physical line structure.

The quality gate checks file existence, row identities, INN completeness, partition totals, expected export row counts, and other consistency conditions. The archived pre-RFSD run passed the quality gate and public export validation.
